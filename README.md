# ТЕХНИКАЛЫҚ ТАПСЫРМА (ТЗ)
## «day by day» — жеке даму күнделігі

**Жобаның жұмыс атауы:** «day by day» 

---

### 1. Жобаның мақсаты
Пайдаланушыға күнделікті уақытын жоспарлауға, жеке ойларын жазуға, мақсаттарын басқаруға, пайдалы әдеттерін бақылауға және көңіл күйін белгілеуге көмектесетін қазақ тіліндегі веб-қосымша жасау.

---

### 2. Жобаның өзектілігі
Оқу, жұмыс және күнделікті міндеттер арасында адам өзіне уақыт бөлуді ұмытып кетуі мүмкін. Қосымша күнделікті әрекеттерді бір жерде ұйымдастыруға және жеке дамуды бақылауға мүмкіндік береді.

---

### 3. Қолданылатын технологиялар
- **Next.js** — веб-қосымшаның негізі.
- **TypeScript** — типтері көрсетілген JavaScript кодын жазу.
- **Tailwind CSS** — интерфейстің дизайнын жасау.
- **VS Code (Visual Studio Code)**: Код жазуға, редакциялауға және терминалмен жұмыс істеуге арналған негізгі редактор.
- **Node.js (LTS нұсқасы)**: JavaScript кодын серверде орындауға арналған орта. Құрамында пакеттерді орнатуға арналған npm немесе pnpm / yarn болады.

> *Ескерту: нақты технологиялар жиынтығы орнату кезінде таңдалады. Барлық технологияны бірден қосу міндетті емес; жобаны кезең-кезеңімен дамытуға болады.*


### 4. Негізгі функционалдық талаптар

#### 4.1. Басты бет
- Күнге байланысты сәлемдесу және ағымдағы күнді көрсету.
- Күннің мотивациялық сөзін көрсету.
- Бүгінгі тапсырмалар мен орындалған әдеттердің қысқаша қорытындысын көрсету.
- Көңіл күйді белгілеуге мүмкіндік беру.

#### 4.2. Күнделік
- Жаңа жазба қосу.
- Жазбаны қарау, өңдеу және жою.
- Жазба күні мен мазмұнын сақтау.
- Бұрынғы жазбаларды қарау.

#### 4.3. Мақсаттарым
- Жаңа мақсат қосу, өңдеу және жою.
- Мақсаттың орындалу мерзімін белгілеу.
- Мақсатты орындалды деп белгілеу.
- Мақсаттардың орындалу күйін көрсету.

#### 4.4. Әдеттерім
- Пайдалы әдеттерді қосу және жою.
- Әдеттің орындалғанын күн сайын белгілеу.
- Орындалған әдеттер санын көрсету.

#### 4.5. Көңіл күй күнделігі
- Күн сайын көңіл күйді таңдау (мысалы: керемет, жақсы, қалыпты, көңілсіз, шаршадым).
- Қалауы бойынша қысқа түсініктеме жазу.
- Бұрын белгіленген көңіл күйлерді күн бойынша қарау.
*(Бұл функция өзіндік бақылауға арналған және медициналық диагноз қоймайды).*

 #### 4.6. Статистика
- Күнделік жазбаларының жалпы санын көрсету.
- Қойылған және орындалған мақсаттарды есептеу.
- Әдеттердің орындалуын апта бойынша көрсету.
- Мақсаттардың орындалу пайызын есептеу.

---

#### Жобаның техникалық негіздемесі — технологиялар мен олардың қажеттілігін түсіндіруге арналған.

#### Frontend және Backend
1. Frontend не үшін қажет?

Frontend — пайдаланушы көріп, қолданатын қосымшаның сыртқы бөлігі. Біздің жобада ол күнделік жазуға, мақсаттар қосуға, әдеттерді белгілеуге және статистиканы көруге мүмкіндік береді.

2. Егер жоба локалды түрде жұмыс істесе, frontend не үшін керек?

Локалды жұмыс істесе де, пайдаланушыға ыңғайлы интерфейс қажет. Frontend батырмаларды, мәзірлерді, карточкаларды және енгізу өрістерін көрсетеді. Ол браузерде жұмыс істей алады, интернет міндетті емес.

3. Backend дегеніміз не?

Backend — қосымшаның серверлік бөлігі. Ол деректерді өңдеу, сақтау, пайдаланушыны авторизациялау және дерекқормен жұмыс істеу үшін қолданылады.

4. Біздің жобамызға Backend міндетті ме?

Міндетті емес. Егер қосымшаны бір компьютерде ғана қолданып, деректерді браузерде сақтасақ, backend-сіз жұмыс істей аламыз. Бірақ аккаунт, бұлттық сақтау немесе бірнеше құрылғыдан қол жеткізу қажет болса, backend керек болуы мүмкін.

5. Frontend пен Backend-тің айырмашылығы қандай?

Frontend — пайдаланушы көретін және басқаратын бөлік, ал backend — серверде деректерді өңдейтін бөлік. Мысалы, frontend-те мақсат қосамыз, ал backend болса, сол мақсатты серверге сақтап бере алады.

#### 2. Локалды жұмыс және деректерді сақтау
6. Локалды түрде жұмыс істеу дегеніміз не?

Бұл — қосымшаның пайдаланушының өз компьютерінде жұмыс істеуі. Жобаны әзірлеу кезінде оны localhost арқылы браузерде ашуға болады. Бірақ localhost-та ашылу барлық дерек міндетті түрде компьютерде сақталады дегенді білдірмейді.

7. Қосымшадағы күнделік жазбалары қайда сақталады?

Қарапайым нұсқада оларды браузердің localStorage қоймасында сақтауға болады. Бұл жағдайда браузер жабылып, қайта ашылса да, деректер әдетте сақталады.

8. localStorage дегеніміз не?

localStorage — браузерде шағын көлемдегі деректерді сақтауға арналған құрал. Біздің жобада оны күнделік жазбаларын, мақсаттарды, әдеттерді және көңіл күйді сақтау үшін қолдануға болады.

9. localStorage қолдансақ, деректер басқа компьютерде ашыла ма?

Жоқ, автоматты түрде ашылмайды. Деректер сол браузерде және сол құрылғыда сақталады. Басқа құрылғыда көру үшін серверлік немесе бұлттық сақтау жүйесі қажет.

10. Интернет болмаса, қосымша жұмыс істей ме?

Иә, егер қажетті файлдар компьютерде қолжетімді болса және қосымша сыртқы интернет қызметтеріне тәуелді болмаса. Бірақ сайтты интернеттен алғаш рет жүктеу немесе серверге қосылу мүмкін болмауы мүмкін.

11. localStorage пен дерекқордың айырмашылығы қандай?

localStorage деректерді браузерде сақтайды, ал дерекқор ақпаратты жүйелі түрде сақтауға мүмкіндік береді. Дерекқор серверде орналасса, деректерді бірнеше құрылғыдан ортақ пайдалануға болады.

12. Компьютер ауыстырғанда деректер жоғалмауы үшін не істеу керек?

Деректерді файлға экспорттау немесе сервердегі дерекқорда сақтау керек. Тек localStorage қолданылған жағдайда браузер деректерін тазалау ақпараттың жоғалуына әкелуі мүмкін.

#### 3. Қолданылатын технологиялар
13. Next.js не үшін қажет?

Next.js — React негізінде веб-қосымшалар жасауға арналған framework. Ол беттерді ұйымдастыруға, навигация жасауға және қажет болса серверлік функцияларды іске асыруға көмектеседі.

14. TypeScript не үшін қажет?

TypeScript JavaScript кодына типтер қосады. Бұл қателерді ертерек анықтауға және кодты түсінікті әрі сенімді жазуға көмектеседі.

15. Tailwind CSS не үшін қажет?

Tailwind CSS интерфейстің дизайнын жасауға арналған. Оның көмегімен түстерді, өлшемдерді, аралықтарды, карточкаларды және мобильді құрылғыларға бейімделетін дизайнды жылдам жасауға болады.

16. T3 Stack дегеніміз не?

T3 Stack — заманауи веб-қосымшалар жасауға арналған технологиялар жиынтығы. Оның құрамына Next.js, TypeScript және басқа да құралдар кіруі мүмкін. Нақты құрам жоба құру кезінде таңдалған конфигурацияға байланысты.

17. Prisma дегеніміз не?

Prisma — бағдарлама мен дерекқор арасында жұмыс істеуді жеңілдететін ORM құралы. Ол деректерді оқу, қосу, өзгерту және жою операцияларын орындауға көмектеседі.

18. tRPC не үшін қажет?

tRPC клиент пен сервер арасындағы функцияларды типтерді сақтай отырып шақыруға мүмкіндік береді. Ол TypeScript қолданылатын жобаларда frontend пен backend арасындағы байланысты жеңілдетеді.

19. Осы технологиялардың барлығы міндетті ме?

Жоқ. Егер жобаның бастапқы нұсқасы тек браузерде жұмыс істеп, деректерді localStorage ішінде сақтаса, Prisma мен tRPC қажет болмауы мүмкін. Технологиялар жобаның нақты талаптарына сай таңдалады.

#### 4 Функционалдық мүмкіндіктер
   
20. Неге жобада күнделік, мақсаттар және әдеттер бөлек бөлімдерге бөлінеді?

Әр бөлімнің өз міндеті бар. Күнделік ойларды жазуға, мақсаттар ұзақ мерзімді жоспарларды бақылауға, ал әдеттер күнделікті әрекеттерді белгілеуге арналған.

21. Мақсаттардың орындалу пайызы қалай есептеледі?

Орындалған мақсаттар санын барлық мақсаттар санына бөліп, 100-ге көбейтеміз.

Мысалы, 5 мақсаттың 3-еуі орындалса:
3/5 * 100 = 60 %

Демек, мақсаттардың орындалу көрсеткіші — 60%.

22. Әдеттердің орындалуын қалай есептейміз?

Әр әдеттің орындалған күндерін белгілейміз. Кейін бір аптада неше рет орындалғанын санап, апта бойынша статистика шығарамыз.

23. Көңіл күй күнделігі не үшін қажет?

Ол пайдаланушыға күнделікті көңіл күйін белгілеуге және уақыт өте келе өз жағдайындағы өзгерістерді байқауға көмектеседі. Бұл медициналық диагноз қоюға арналмаған.

24. Күннің мотивациялық сөзі қалай көрсетіледі?

Алдын ала дайындалған мотивациялық сөздер тізімін қолдануға болады. Күн сайын сол тізімнен бір сөз көрсетіледі. Бұл үшін міндетті түрде интернет немесе сыртқы API қажет емес.

25. Деректерді қосу, өңдеу және жою дегеніміз не?

Бұл CRUD операциялары деп аталады: Create — қосу, Read — оқу, Update — өзгерту, Delete — жою. Біздің жобада олар күнделік жазбаларына, мақсаттарға және әдеттерге қолданылады.

#### 5. Қауіпсіздік және жариялау

26. Егер қосымша бір адамға арналған болса, авторизация қажет пе?

Міндетті емес. Егер қосымша бір құрылғыда ғана қолданылса, авторизациясыз жұмыс істей алады. Бірақ жеке аккаунт және бірнеше құрылғыдан қол жеткізу керек болса, авторизация қосқан дұрыс.

27. localStorage қауіпсіз бе?

Ол құпия ақпаратты сақтауға арналған толық қорғалған қойма емес. Браузердегі JavaScript оған қол жеткізе алады. Сондықтан құпиясөздерді немесе өте сезімтал мәліметтерді онда сақтамаған дұрыс.

28. GitHub не үшін қажет?

GitHub жобаның бастапқы кодын сақтауға, өзгерістер тарихын бақылауға және жобамен бірлесіп жұмыс істеуге мүмкіндік береді.

29. GitHub-қа жүктелген жоба автоматты түрде сайтқа айнала ма?

Жоқ. GitHub репозиторийі — код сақталатын орын. Сайтты интернетте ашу үшін GitHub Pages немесе Vercel сияқты хостингке жариялау қажет. Next.js жобасының барлық серверлік мүмкіндіктерін GitHub Pages қолдамайды.

30. Қосымшаны телефонға бейімдеу үшін не істеу керек?

Responsive дизайн жасау керек. Tailwind CSS арқылы экран өлшеміне байланысты карточкалардың, мәзірлердің және басқа элементтердің орналасуын өзгертуге болады.

#### 6. Жобаға қатысты қосымша маңызды сұрақтар
31. Бұл жобада неге Next.js таңдалды?

Next.js бірнеше бетті бір жобада ұйымдастыруға және React компоненттерін қолдануға мүмкіндік береді. Сонымен қатар, болашақта backend қосып, жобаны кеңейтуге болады.

32. Қосымшаның дизайнын өзгерту үшін кодты қайта жазу керек пе?

Толық қайта жазу қажет емес. Tailwind CSS арқылы түстерді, қаріптерді, карточкалардың өлшемдерін және элементтердің орналасуын өзгертуге болады.

33. Жоба дайын болғанын қалай тексереміз?

Әр функцияны жеке тексереміз: жазба қосу, өңдеу, жою, мақсатты орындалды деп белгілеу, әдеттерді бақылау және статистиканың дұрыс есептелуі. Сонымен қатар, телефон мен компьютердегі көрінісін тексереміз.

### 5. Интерфейске қойылатын талаптар
- Интерфейс толықтай қазақ тілінде болуы керек.
- Дизайн заманауи, қарапайым және қолдануға ыңғайлы болуы керек.
- Ұсынылатын түстер: ашық күлгін, ақшыл қызғылт, ақ және жұмсақ жасыл.
- Карточкалар, түсінікті иконкалар және жеңіл анимациялар қолданылуы мүмкін.
- Сайт телефонға да, компьютерге де бейімделуі керек (Responsive).
